# 性能与显存

这里区分模块耗时、端到端交互和显存采样。除特别说明外，实测平台是 NVIDIA H200，单会话，FlashHead Lite 512 × 512 / 25 FPS，MiniCPM-o 4.5 BF16 + SDPA。结果来自本项目的真实运行，不能直接套用到其他显卡。

## 显存

2026-10-15，从四张卡空闲状态启动四卡服务，复用已有磁盘编译缓存；记录模型加载与预热、90 秒摄像头会话、仅音频输入驱动数字人、浏览器打断回归，最后停止服务。摄像头目标 5 FPS；视觉上下文 24 单元、旧回复最多 500 tokens；脑模型和视频模型编译开启，声码器编译关闭。

**本轮观察到单卡最高约 22.00 GiB，四卡同时最高约 39.37 GiB。**

| 物理 GPU | 工作内容 | 整卡观察峰值 MiB | GiB |
| --- | --- | ---: | ---: |
| 4 | MiniCPM 编码器 / 理解 / LLM | 22,532 | 22.00 |
| 6 | MiniCPM 原生 TTS / 声码器 | 7,502 | 7.33 |
| 5 | FlashHead Lite / wav2vec2 / VAE | 6,356 | 6.21 |
| 7 | faster-whisper-large-v3 字幕 | 3,926 | 3.83 |
| 四卡同一次采样合计 | 全流水线 | **40,316** | **39.37** |

| 阶段 | GPU 4 | GPU 6 | GPU 5 | GPU 7 | 同时总峰值 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 启动与预热 | 22,270 | 7,494 | 6,210 | 3,926 | 39,676 |
| 摄像头 + 数字人 | 22,532 | 7,502 | 6,356 | 3,926 | 40,316 |
| 仅音频输入 + 数字人 | 20,358 | 7,490 | 6,356 | 3,926 | 37,906 |
| 浏览器交互回归 | 20,372 | 6,682 | 6,356 | 3,926 | 37,106 |

阶段表单位为 MiB；各卡单独峰值不一定同时出现。后一阶段复用同一组模型进程，保留分配可能受前一阶段影响，不能视为每个模式独立冷启动的最低需求。

### 测量口径

- 采集 `nvidia-smi memory.used`，覆盖模型运行时的子进程、CUDA 上下文与缓存分配；使用整卡数值，避免漏计子进程。不是仅统计 PyTorch 活跃张量。
- 采样持续 657.0 秒，共 438 个有效样本。请求间隔 200 ms，受 `nvidia-smi` 执行开销影响，**实际间隔中位数 1.404 秒、最长 11.0 秒**。
- 四张被测卡启动前、停止后均为 1 MiB；其他任务使用 GPU 0–3。停止后确认全部本项目服务退出。
- 这是本工作负载的**采样峰值**，可能漏掉短暂分配；并非理论最大值、完全空编译缓存的峰值或长期压力测试上限。实际显存随输入、上下文、编译形状和软件版本变化。

去除进程 ID、会话与私有路径的 [JSON 测量汇总](benchmarks/memory-2026-10-15.json) 随仓库发布。复测命令见 [测试指南](testing.md#显存复测)。

### 容量规划

按每张卡留出余量，而不是只检查总显存。按本轮结果预留至少约 30% 作为起点，可将理解卡按 ≥32 GiB、原声与视频卡各 ≥12 GiB、字幕卡 ≥8 GiB 规划；这是容量预算建议，**未验证为这些规格显卡的最低可运行配置**。尤其不能由约 22 GiB 的采样结果推断任意 24 GB 卡都能稳定运行。

当前验证平台每卡 143,771 MiB（约 140.4 GiB）。H200 上的推理速度不代表显存容量相近的其他卡。降低上下文或关闭编译可能改变占用，但需要重新测速度与峰值。

## torch.compile

以下为前期受控基准，固定相同输入和倾听决策，排除首次预热；脑模型视觉输入是每单元一帧，不能与最终 5 FPS 测试直接比较。

| 模块与范围 | eager 中位数 | compiled 中位数 | 比值 |
| --- | ---: | ---: | ---: |
| MiniCPM 纯音频 prefill + 倾听决策 + finalize | 88.671 ms | 47.275 ms | 1.88× |
| MiniCPM 单帧视觉 + 音频，同上 | 187.240 ms | 103.683 ms | 1.81× |
| FlashHead 960 ms 静音驱动块 | 218.267 ms | 118.901 ms | 1.84× |

脑模型每项统计 16 个暖态样本，不能由倾听基准推导原声生成或首音延迟。视频每项统计 12 块，包含重采样、音频编码、DiT、VAE 和回传 CPU，排除视频编码与网络。复测入口是 `scripts/benchmark_compile.py`。

正式配置编译 `llm.model`、`tts.model`、FlashHead DiT 和 VAE；原生声码器保持 eager。启动时覆盖多种采样帧数及上下文淘汰，避免第一次长会话碰到未预热的分支。

## 四卡并行的收益与边界

| 对照实验 | 原配置 | 分卡配置 | 解释 |
| --- | ---: | ---: | --- |
| FlashHead Lite 960 ms 块，已编译 | 单卡 128.202 ms | 双卡序列并行 268.674 ms | 本机双卡约慢 2.1 倍，正式视频工作器保持单卡 |
| MiniCPM 积压回放，发声块输入处理确认中位数 | 同卡理解 / 语音 445.29 ms | 分卡 184.67 ms | 理解可提前接收下一块 |
| 同次实验，从提交到语音交付的中位数 | 447.41 ms | 832.88 ms | 快速提交使语音排队；输入确认提前不能等同首音加速 |

视频对照每种配置 14 块，丢弃前 4 块。MiniCPM 对照提交相同 32 块、30.72 秒录音，按 ACK 尽快回放；两次随机输出分别产生 117 / 96 个语音 token，因此不报告严格的整体吞吐加速比。分卡记录到 22 对理解 / 原声服务区间重叠，共约 2.71 秒；这些是服务区间统计，不是 CUDA 内核时间线。

四卡分配的目标是让输入处理、语音、数字人、字幕在独立的工作阶段重叠执行。队列设置了上限；推理长期慢于实时速度时仍需要降低负载或排查瓶颈。

## 本次发布的真实链路验收

2026-10-15，同一组四卡服务，顺序执行以下测试，均通过：

| 测试 | 结果 |
| --- | --- |
| 视觉 + 数字人，90.3 秒 | 蓝色 → 绿色 → 人物 → 上下文淘汰后蓝色，回答与画面对应 |
| 摄像头采样 | 目标 5 FPS；实测约 4.82 FPS，间隔中位数 200 ms；浏览器阻塞时跳过漏采槽位，不复制当前帧补历史 |
| 视觉链路计数 | 429 帧收到 / 429 帧处理；上下文最大 24 单元；处理 ACK 时待处理输入最大 0 |
| MiniCPM 输入处理 | 中位数 176.9 ms，P95 352.4 ms；不包含异步原声和 A2V 延迟 |
| 仅音频输入 + 数字人 | 视觉 slices 为 0；原声交付逐采样一致；4.12 秒语音、120 帧视频（含句尾画面） |
| 浏览器回归 | H.264、独立媒体 / 控制、重复打断、倾听动作、字幕 / 时间戳、响度、纯音频输出与重连通过，页面错误 0 |
| 一次手动打断样本 | 确认 48 ms、停止声音 35 ms、进入倾听画面约 814 ms，旧批次媒体 0 |

单次打断读数不是延迟分位数。测试使用模拟麦克风 / 摄像头和真实 GPU 模型，尚未统计真人插话成功率或长达数小时的稳定性。公开 [验收汇总](benchmarks/validation-2026-10-15.json) 不含原始媒体与会话信息。

此前还完成过 4 分钟共享带宽弱网测试（2,400 ms RTT、下行 4 Mbps、上行 1 Mbps）：240 块输入均完成，未观察到输入等待持续增长。该记录主要使用低视觉负载和倾听画面，不代表同等网络条件下 5 FPS 摄像头的带宽保证。
